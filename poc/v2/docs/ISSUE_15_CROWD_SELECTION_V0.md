# Issue #15 — Living World Crowd Selection v0

## 為何做
玩家在近景中看到大量重疊的小人，同格角色的選取也只取最近世界座標，因此無法辨識特定真人，也難以跟隨觀察。已有軍隊視覺左右錯位，但普通居民與 UI 點擊沒有統一的角色顯示位置。

## 實作與遊玩方式
分支 `codex/issue-15-crowd-selection-v0` 自已通過 CI 的 Living World `11b075c` 建立；`main` 不動，不自行合併。

- **同格的人使用穩定角色 ID** 的顯示槽位（不是改動個人真實座標）。一般居民也會縮小並錯開，停頓、速度及沿真實路徑補間仍可正常觀察。
- 1× 全圖：人數多的地方只畫代表人物與**人數圈標**；點圈標開啟所有真人名單。
- 4×：最多分開畫 5 名人物；8×：最多 8 名。10 人以上（或其他超出顯示容量）的居民仍完整保存在名單，可翻頁挑選；已選居民優先保留在畫面，避免選完又消失。
- 群聚名單位於地圖內的有界疊層：5 名居民／頁，顯示名字、目前真實行動及健康。點「觀察」進入原居民分頁，點「跟隨」直接追蹤真人，關閉／頁碼按鈕可用鍵盤操作。關閉地圖圖層與切換模擬速度不影響名單所指真實 ID。
- 地圖點選不再任意選最近世界座標：**角色繪製、個別 hit test、受傷者 Heal 選人、Priest 泡泡**共用同一個展示位置。近景優先選可見的人；最遠全圖保留既有重要地圖標記的優先序。
- 角色在畫面上偏移不會產生實體接觸、資源、攻擊或信仰證據；所有 Miracle 依原 `S.castMiracle()` 在真實世界座標判定。畫面排序、群聚、站位和名單不存入世界 JSON。
- 原 #14 外交／礦權／軍事圖層、#15 Living World Camera／真正 8h tick、存讀與決定性 replay 都保留。**不更動 `sim.js`、`politics.js`、`mobility.js`、Profile。**

## 驗證
Node.js 24、單 CI Job ≤3 分鐘。`crowd-selection.test.cjs` 用 2／5／10 人與 1×／4×／8× 測試不重疊、個別命中、群聚名單、翻頁、跟隨、實際 Heal 命中，並確認 JSON 與事件規則不被 UI 修改。連同既有 Camera／Prayers／Miracle／地圖圖層／戰事／Smoke／離線 playable 一致性作精簡回歸。

## 人工試玩條件與限制
可沿用原自然河谷或真實第 303 日存檔。放大密集村落後，分別點出 2、5、10 人群聚，確認確實能看清、選到指定人、追蹤他的行動；再觀察真正受傷者的 Heal 前後。人物視覺分開不是模擬上改變站位；大聚集區只顯示部分人物，剩餘需在選人清單中查看。此階段為可玩 UX 切片，**沒有聲稱已通過真人趣味驗收**；未來仍可能需要角色美術、表情與相鄰群聚的畫面避讓調整。
