# Issue #15 — Gameplay-First 第一個玩家決策切片

## 基準與目的
以 `codex/issue-14-map-layer-toggles` HEAD `273e6bce` 為基準，繼承已核實地圖圖層。維持 `main` 不動。
首輪只修真實需求→可選介入與 Miracle 施放→可查證後果兩個缺口；不修改世界 kernel、居民／AI、資源、信仰40核心門檻、礦權或戰爭。

## 來源碼觀察
- 既有 needs card 可定位，卻沒有直接連到可考慮的 Miracle；選能力再瞄準有額外操作成本。
- 施法後的 Toast 很短，歷史資料不容易讓玩家看出「已施放」與「真正回應祈求」差別。
- 角色仍缺輕量回訪／近期經歷索引；留待優先鏈完成後，用真人試玩決定修不修。

## 首輪 patch 的具體行為
- 可定位的祈求旁新增可選「選喚雨／選豐收／選治療／選效率祝福」。只預選 Miracle 與目標中心，評估當下 DP／目標合法性，**沒有自動施放**；需玩家再點地圖。舊定位按鈕保留。
- 需求卡顯示已等待時間。缺雨祈求顯示真實回應驗證時限（60 模擬日）；不可誤當降雨效果的持續時間。
- 「需求」分頁新增可查看的最近一次成功施法紀錄：施法日、座標、實際 DP、已直接影響目標；只有施法同步造成、具備 God 歸屬的 Devotion 變化才計入當刻證據。
- 喚雨只有雨雲建立時顯示「已施放、待驗證」。只有本次雨雲 `effectId` 與真實祈求 `castId` 相符，且既有 simulator 已記錄 `status=answered`（含水改善＋真實產糧），才標為「已核實」；不同施法不能借用成果。否則明確列出尚待核實、已失效或無法歸因。
- 最近介入資料屬瀏覽器短期觀察，重新創世／讀檔時清除，不進世界存檔；真實世界事件與農產驗證仍由原模擬引擎負責。
- 有最近介入紀錄時需求每頁 2 件，平時仍 3 件，保持固定 Inspector、沒有增加網頁捲動。

## 人工遊玩驗收（待執行）
選「自然河谷」或匯入未經注入的真實中盤 JSON（例如已保存第303日世界）。**30 人預設宗教對決不是正常世界玩法驗收樣本。**
請 3–5 位未看設計文件的玩家，各玩 10–15 分鐘，記錄：
1. 何時首次發現可理解的真實需求／戰爭／居民問題，能否定位與解釋情境。
2. 點「選喚雨」是否明白還沒花 DP，仍需地圖點擊，並能選擇不介入。
3. 施法後能否區分立即效果與已確認的長期信仰／糧食效果，有沒有錯誤歸因。
4. 等待或 16× 快轉的時間、不得不暫停的操作，能否主動指出下一個想處理的問題。
質性紀錄優先，不拿自動測試、戰爭次數、模擬長跑代替真人驗收。

## 工程護欄
- Node.js 24；GitHub Actions 單 job <=3 分鐘；快速 UI 契約、圖層／戰況迴歸、Smoke、離線 HTML 一致性。
- 出現 CI failure 先讀 job log 精確修復；不將一般斷言錯誤混為 timeout。
- 本輪沒有調整 AI 或增加事件生成頻率；不承諾 5–10 分鐘內一定觸發劇情。
