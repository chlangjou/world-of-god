# Oracle Faith Defense Matrix v0.1 — 實驗結果

**日期**：2026-10-14（Asia/Taipei）  
**功能分支**：`feature/opponent-difficulty-profiles-v0.3`；`main` 未修改。  
**性質**：獨立、可調整、可回退的實驗矩陣；不是最終數值平衡。

## 1. 精確定義：不是每個 Tick 的信仰傷害

矩陣的**行**是「正在防禦的居民所遵從的 Oracle」，**列**是「具備可追溯成果的對手 Oracle」。數字是信仰防禦倍率。

| Defender \ Challenger | 預設（含 Reset、傳教） | 存糧 | 育兒 | 探索 |
| --- | ---: | ---: | ---: | ---: |
| **預設** | 1.0 | 0.8 | 0.8 | **1.0（未指定）** |
| **存糧** | 1.2 | 1.0 | 0.4 | 1.6 |
| **育兒** | 1.2 | 1.6 | 1.0 | 0.4 |
| **探索** | **1.0（未指定）** | 0.4 | 1.6 | 1.0 |

「探索 vs 預設」在需求中尚未指定，因此雙向維持 1.0；不推定成 1.2:0.8。「同策略」永遠是 1.0:1.0。 `religion.spread` 是另一種行為方向，但**不額外構成一種屬性防禦**，暫等同預設防禦。有效 `life.balance` Reset 解除該 Saint 的特化，不追溯移除已生成的食物、建築和人口。

**受限的機會率模型**：當且僅當存在「目標真實缺口 + 對方真正產生的成果 + 現有社群佈道接觸」時：

```js
effectiveEncounterChance = Math.min(faithDefenseChanceCeiling,
  counterContactChance / defenderFaithDefenseMultiplier)
```

本版初始基準 `counterContactChance = 0.45`、上限 0.90。因此對 **40% 防禦**的受證據挑戰者，機率被上限限制在 0.90；**160% 防禦**為 0.45/1.6 = 0.28125；100% 為 0.45；80% 為 0.5625；120% 為 0.375。**倍率是防禦係數，不保證每次遊戲事件嚴格按 1.6:0.4 人數比例變化。** 信徒 Devotion 不會因神諭發布直接變動。事件首次動搖之後，只有同一接觸來源的近期真實佈道者，才可能進行有限時效的後續說服；每次依居民*當前*方針重新計算防禦，故 Reset 可以減少已形成的策略弱點。普通傳教仍不能直接突破核心 **40+**；改宗仍須經既有較低的 Devotion 條件，攻擊型 Miracle 的 Presence 限制未修改。

## 2. 同一 Day-45 存檔、8 組各續跑 60 日

固定 `dry-stress`、同一真實世界 RNG / 人口 / 土地 / 聖徒 / AI、`standard` AI。僅在分叉時透過**合法** `issueOracle` 改方針；每個組別不假造需求、存糧、住房或信徒。AI 後續照原決策跑，非每 Tick 最佳化。原 AI 核心 40+ **12 人**；每一天記錄原核心是否曾跌破 40，避免只看終點。

| 策略（玩家對 AI） | 信仰倍率 | Day105 核心 40+ 玩家:AI | 原12名 AI 核心曾 <40 | 原12名改宗玩家 |
| --- | --- | ---: | ---: | ---: |
| 玩家被動 / AI 存糧 | 本案矩陣 | 3:12 | 0 | 0 |
| 存糧 / 存糧 | 本案矩陣 1:1 | 8:12 | 0 | 0 |
| 育兒 / 存糧 | 關閉矩陣（前版 v0.1 接觸規則） | 3:8 | 4 | 0 |
| 育兒 / 存糧 | 全部 1.0（同樣接觸路徑） | 2:10 | 2 | 0 |
| **育兒 / 存糧** | **本案 1.6:0.4** | **3:5** | **8** | **1** |
| 育兒30日 → Reset → 存糧 / AI 存糧 | 本案矩陣 | 7:10 | 2 | 1 |
| 存糧 / 探索 | 本案 1.6:0.4 | 7:12 | 0 | 0 |
| 探索 / 育兒 | 本案 1.6:0.4 | 3:12 | 0 | 0 |

最強組證明**自然世界可以發生有真實證據的核心動搖及改宗**，但不代表每場可照此翻盤。與全 1.0 的嚴格對照是 **2 → 8 名原核心曾低於40**，但只出現 **1 人改宗**。因為日常世界有個人需求和隨機生活決策，同一 Seed 在倍率改變後事件序列會分岔，不能把所有人口差異簡化為一次倍率乘法。

失敗也很有資訊量：探索需要可行的新房屋、拓荒或居住不足；在這個短期世界，住房需求小，Oracle 即使提升建材與施工優先度，也無法憑空生成可建房屋；而存糧對探索若沒有可比的真實糧食不足，也不會有宗教動搖。**不能把這兩組 0 人的結果寫成相剋已完成。**

## 3. 兩個其他世界的相同配對（60日）

只測最容易產生成果的**玩家育兒 vs AI 存糧**，對照全 1.0 與本案矩陣；AI 後續仍使用標準決策。

| Seed | 分叉時原 AI 核心 | 全 1.0：曾低於40 | 本案矩陣：曾低於40 | 原核心改宗（1.0 → 本案） |
| --- | ---: | ---: | ---: | ---: |
| `opponent-competition-replay` | 6 | 2 | 2 | 0 → 0 |
| `valley-spring-01` | 5 | 1 | 1 | 0 → 1 |

這說明**提高相剋係數並非每次都讓更多人跨越 40**；有些場景增加的是後續改宗可能性或改變其他居民的信仰軌跡。此為三種 Seed 的小量短期探索，不是統計顯著性的平衡結論。

## 5. 待處理的真正機制缺口

1. **探索缺實際成果入口**：只有提高工作分數不足以產生住房需求、可建築的家戶或外拓活動。另需一個小型、真正可自主觸發的拓荒/住房需求鏈；不應為了模擬而人工添加居民或增加宗教 Buff。
2. **存糧的受害場景不足**：要觸發存糧對探索的優勢，須當地糧食真的不足且外村有真實儲備。現在農業很強、土地很充足，短期內很少自然成立。
3. **比例可能過猛**：40% 防禦在目前 45% 基準接觸率下，因上限變成 90% 的成功抽樣機會。原12名核心 60日內有8名曾跌破40，是值得觀察的壓力；**不是已驗證的最終平衡**。先檢查三組相剋都能自然發生，再考慮基礎接觸率調整，不必拉長到幾年的模擬。
